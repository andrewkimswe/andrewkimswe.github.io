# VPC 퍼블릭/프라이빗 서브넷 설계 노트

## 목표

외부에 노출되는 리소스와 내부에서만 동작해야 하는 리소스를 분리해 기본적인 네트워크 경계를 만든다.

## 기본 구조

- 퍼블릭 서브넷: ALB, Bastion처럼 인터넷에서 접근이 필요한 리소스
- 프라이빗 서브넷: ECS Task, RDS처럼 직접 노출되면 안 되는 리소스
- Internet Gateway: 퍼블릭 서브넷의 인터넷 통로
- NAT Gateway: 프라이빗 서브넷에서 외부 API나 패키지 저장소로 나가는 통로

## 라우팅 기준

퍼블릭 서브넷의 라우팅 테이블은 `0.0.0.0/0`을 Internet Gateway로 보낸다.

프라이빗 서브넷의 라우팅 테이블은 `0.0.0.0/0`을 NAT Gateway로 보낸다. 외부에서 프라이빗 서브넷으로 직접 들어오는 경로는 만들지 않는다.

## 체크 포인트

- NAT Gateway는 가용 영역별로 두는 것이 안정적이다.
- RDS는 public access를 끄고 보안 그룹으로 접근 주체를 제한한다.
- ALB 보안 그룹은 80/443만 열고 애플리케이션 보안 그룹은 ALB만 허용한다.

## 배운 점

VPC 설계는 리소스 배치보다 트래픽 방향을 먼저 그리는 것이 이해하기 쉽다.
