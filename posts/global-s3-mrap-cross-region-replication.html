[AWS] 글로벌 S3 아키텍처 구성하기 - Multi-Region Access Point와 Cross-Region Replication

글로벌 서비스에서 S3를 여러 리전에 구성할 때는 요청을 어디로 보낼지와 데이터를 어떻게 복제할지를 분리해서 생각해야 한다. MRAP와 CRR의 역할을 나누어 정리한다.

2026.08.05 AWS S3 Multi-Region

글로벌 서비스를 운영하다 보면 하나의 AWS 리전에 데이터를 저장하는 것만으로는 부족한 경우가 있다. 예를 들어 한국과 미국 사용자가 동일한 서비스를 사용하고 있다고 가정해보자.

서울 리전에만 S3 버킷이 있다면 미국 사용자의 요청도 서울까지 전달되어야 한다. 반대로 각 리전에 S3 버킷을 하나씩 만든다면 애플리케이션에서 어느 버킷으로 요청할지 결정해야 하고, 특정 리전에 장애가 발생했을 때의 처리도 고려해야 한다.

이런 상황에서 사용할 수 있는 기능이 Amazon S3 Multi-Region Access Point(MRAP)이다.

1. 문제 상황

다음과 같은 요구사항이 있다고 가정한다.

  • 서울과 미국 리전에 각각 S3 버킷이 존재한다.
  • 사용자는 가능한 가까운 리전으로 접근해야 한다.
  • 인터넷 구간의 영향을 줄이고 AWS 글로벌 네트워크를 활용하고 싶다.
  • 애플리케이션에서는 리전별 S3 endpoint를 직접 관리하고 싶지 않다.
  • 특정 리전에 문제가 발생하더라도 다른 리전에서 데이터를 제공할 수 있어야 한다.

단순히 두 개의 S3 버킷을 생성하는 것만으로는 이러한 요구사항을 모두 해결하기 어렵다.

flowchart TB client[Client] seoul[Seoul S3 Endpoint] us[US S3 Endpoint] app[Application chooses endpoint] client --- app app --- seoul app --- us

애플리케이션이 직접 사용자의 위치와 리전 상태를 판단한다면 라우팅과 장애 처리 로직이 애플리케이션에 들어가게 된다.

2. Multi-Region Access Point

Multi-Region Access Point는 여러 AWS 리전의 S3 버킷을 하나의 Global Endpoint 뒤에 구성할 수 있게 해준다.

flowchart TB users[Users] mrap[S3 Multi-Region Access Point
Global Endpoint] seoul[Seoul S3 Bucket] us[US S3 Bucket] users --- mrap mrap --- seoul mrap --- us

애플리케이션은 각 리전의 S3 endpoint를 직접 선택할 필요 없이 하나의 MRAP endpoint로 요청한다. MRAP는 요청을 처리할 수 있는 버킷 가운데 네트워크상 가까운 버킷으로 요청을 라우팅한다.

3. AWS Global Network를 통한 요청 라우팅

Multi-Region Access Point의 중요한 특징 중 하나는 단순한 DNS 기반 리전 선택 기능이 아니라는 것이다. MRAP의 글로벌 endpoint로 전달된 인터넷 기반 요청은 AWS Global Accelerator를 활용하여 AWS 글로벌 네트워크를 통해 적절한 S3 버킷으로 전달된다.

flowchart TB user[User] mrap[MRAP Global Endpoint] network[AWS Global Network] seoul[Seoul S3] us[US S3] user --- mrap mrap --- network network --- seoul network --- us

따라서 글로벌 사용자를 대상으로 S3 기반 애플리케이션을 구성할 때 네트워크 라우팅을 애플리케이션에서 직접 구현해야 하는 부담을 줄일 수 있다.

4. MRAP만 구성하면 생기는 문제

여기서 중요한 점이 있다. Multi-Region Access Point는 각 버킷의 객체 내용을 확인한 뒤 라우팅하는 서비스가 아니다.

예를 들어 다음과 같은 상황을 생각해보자.

Seoul Bucket
└── image.jpg

US Bucket
└── 없음

MRAP가 네트워크 근접성을 기준으로 US 버킷으로 요청을 보냈는데, US 버킷에 image.jpg가 없다면 결과는 404 Not Found다.

MRAP는 Request Routing을 해결하지만 Data Replication 자체를 해결하지 않는다.

5. 그래서 Cross-Region Replication이 필요하다

각 리전의 버킷에 동일한 데이터를 유지하기 위해 S3 Cross-Region Replication(CRR)을 함께 구성할 수 있다.

flowchart TB users[Users] mrap[Multi-Region Access Point
Global Endpoint] seoul[Seoul Bucket] us[US Bucket] crr[Cross-Region Replication] users --- mrap mrap --- seoul mrap --- us seoul --- crr crr --- us
MRAP
어느 리전으로 요청을 보낼 것인가?
CRR
각 리전에 필요한 데이터를 어떻게 복제할 것인가?

서울에서 새로운 객체가 업로드되었다면 CRR을 통해 미국 리전에도 해당 객체를 복제할 수 있다. 양쪽 리전 모두에서 쓰기가 발생하는 Active-Active 구조라면 양방향 replication도 고려할 수 있다.

6. Active-Active 구조

MRAP는 Active-Active routing을 구성할 수 있다.

flowchart TB mrap[MRAP] seoul[Seoul
Active] us[US
Active] mrap --- seoul mrap --- us

모든 활성 리전이 요청을 받을 수 있고 MRAP가 가까운 활성 리전으로 요청을 라우팅한다. 다만 Active-Active라고 해서 자동으로 두 버킷의 내용이 동일해지는 것은 아니다. 데이터 동기화 전략은 별도로 설계해야 한다.

7. Active-Passive와 Failover

장애 복구가 더 중요한 시스템에서는 Active-Passive 구성도 가능하다.

flowchart TB normal[Normal] seoulActive[Seoul
Active] usPassive[US
Passive] failover[Failover] seoulPassive[Seoul
Passive] usActive[US
Active] normal --- seoulActive normal --- usPassive failover --- seoulPassive failover --- usActive

서울 리전의 트래픽을 다른 리전으로 전환해야 하는 상황에서는 routing status를 변경하여 트래픽을 전환할 수 있다. 이 구조에서는 CRR을 이용해 standby 리전에도 필요한 데이터가 준비되어 있도록 하는 것이 중요하다.

8. 전체 아키텍처

정리하면 글로벌 S3 아키텍처를 다음처럼 구성할 수 있다.

flowchart TB users[Global Users] mrap[S3 Multi-Region Access Point
Global Endpoint] seoul[ap-northeast-2
S3 Bucket] us[us-east-1
S3 Bucket] crr[Cross-Region Replication] users --- mrap mrap --- seoul mrap --- us seoul --- crr crr --- us

각 구성 요소의 역할은 명확하다.

9. 언제 사용하면 좋을까?

MRAP + CRR 구조는 특히 다음과 같은 상황에서 유용하다.

  • 전 세계 사용자가 대용량 객체를 업로드하는 서비스
  • 글로벌 미디어 플랫폼
  • 멀티 리전 애플리케이션
  • S3 기반 중요 데이터의 리전 장애 대응
  • 글로벌 사용자의 S3 접근 성능 개선
  • 애플리케이션의 리전별 endpoint 관리 부담을 줄이고 싶은 경우

반대로 사용자가 대부분 하나의 지역에 있고 멀티 리전 장애 복구 요구도 없다면 일반적인 단일 리전 S3 구조가 더 단순하고 경제적일 수 있다.

10. 정리

Multi-Region Access Point와 Cross-Region Replication은 서로 비슷해 보이지만 해결하는 문제가 다르다.

Multi-Region Access Point
Routing
Cross-Region Replication
Data Replication

MRAP는 하나의 글로벌 endpoint를 통해 여러 리전의 S3 버킷으로 요청을 라우팅하고, CRR은 각 버킷에 필요한 객체를 복제한다. 따라서 글로벌 S3 아키텍처를 설계할 때는 단순히 "여러 리전에 버킷을 만든다"에서 끝나는 것이 아니라, Traffic Routing과 Data Replication을 별도의 문제로 보고 설계하는 것이 중요하다.
