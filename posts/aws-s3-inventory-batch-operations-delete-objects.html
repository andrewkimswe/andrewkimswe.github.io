AWS · S3 · Serverless

[AWS/S3] 수백만 개의 오래된 S3 객체를 서버리스로 삭제하려면? - S3 Inventory와 Batch Operations

S3 객체가 수백만 개로 늘어나면 직접 list-delete loop를 돌리는 방식은 작업 상태, retry, 실패 복구까지 직접 책임져야 한다. S3 Inventory와 Batch Operations를 사용하면 대상을 정의하고 관리형 서비스에 실행을 맡길 수 있다.

2026.08.26AWSS3Batch Operations

S3 버킷에 객체가 몇백 개 있다면 삭제 작업은 어렵지 않다. 하지만 수백만 개 객체가 여러 prefix와 Glacier Deep Archive에 걸쳐 있다면 문제의 성격이 달라진다.

3년 이상 된 객체는 삭제한다. 단, 별도로 지정된 일부 객체는 계속 보존한다.

이때 애플리케이션에서 모든 객체를 하나씩 조회하고 삭제하는 방식은 비효율적이다. 대규모 S3 객체 작업을 위해 AWS는 S3 Inventory와 S3 Batch Operations를 제공한다.

1. 문제를 두 단계로 나누자

flowchart TB target[어떤 객체를 처리할 것인가?] --> inventory[S3 Inventory] action[그 객체들에 어떤 작업을 실행할 것인가?] --> batch[S3 Batch Operations]

첫 번째는 대상 객체를 식별하는 문제고, 두 번째는 대량 작업을 실행하는 문제다.

2. S3 Inventory란?

S3 Inventory는 버킷의 객체 목록과 metadata를 정기적으로 생성할 수 있는 기능이다.

Bucket
Key
Version ID
Size
Last Modified Date
Storage Class
Encryption Status
flowchart TB bucket[S3 Bucket
millions of objects] --> inventory2[S3 Inventory] inventory2 --> report[Object Metadata Report]

수백만 개 객체의 상태를 분석하기 위해 매번 애플리케이션에서 객체를 하나씩 나열할 필요 없이 S3가 생성한 inventory report를 기반으로 처리 대상을 결정할 수 있다.

3. 왜 Inventory가 유용할까?

대규모 객체 관리에서는 list, check, filter, process를 애플리케이션에서 직접 반복하는 것보다 이미 생성된 inventory를 이용하는 편이 관리하기 쉽다.

LastModified < 3 years ago
AND
Preserve != true

핵심은 실제 데이터를 복원해서 읽는 것이 아니라 객체 metadata를 이용해 관리 대상을 결정한다는 점이다.

4. S3 Batch Operations란?

대상 객체가 정해졌다면 수십만 개에서 수백만 개 객체에 같은 작업을 실행해야 한다. 이를 위한 기능이 S3 Batch Operations다.

flowchart TB manifest[Object Manifest] --> batch2[S3 Batch Operations] batch2 --> o1[Object 1] batch2 --> o2[Object 2] batch2 --> o3[Object 3] batch2 --> on[Object N]

S3 Batch Operations는 대규모 객체 집합에 반복적인 작업을 관리형 방식으로 수행할 수 있다. 직접 EC2 worker fleet을 만들고 작업 분배, retry, progress tracking을 구현할 필요를 줄인다.

5. Lambda와 결합하기

객체별로 단순 기본 작업 이상의 custom logic이 필요하면 Batch Operations에서 Lambda를 호출하는 구조를 사용할 수 있다.

flowchart TB inventory3[S3 Inventory] --> candidates[Target Objects] candidates --> batch3[S3 Batch Operations] batch3 --> lambda[Lambda] lambda --> decision{Preserve?} decision -->|YES| skip[Skip] decision -->|NO| delete[Delete]

이렇게 하면 EC2 기반의 별도 batch processing infrastructure 없이 serverless하게 처리할 수 있다.

6. 전체 구조

flowchart TB s3[Amazon S3
millions of objects] --> inv[S3 Inventory] inv --> metadata[Object metadata] metadata --> filter[대상 객체 식별] filter --> ops[S3 Batch Operations] ops --> fn[Lambda] fn --> preserve[Preserve] fn --> remove[Delete] 
Inventory        = 무엇을 처리할 것인가
Batch Operations = 대규모로 어떻게 실행할 것인가
Lambda           = 객체별 어떤 custom logic을 적용할 것인가

7. 왜 EC2에서 스크립트를 돌리지 않을까?

EC2에서도 inventory를 읽고 loop를 돌며 DeleteObject를 호출할 수 있다. 하지만 EC2 provisioning, OS 관리, scaling, failure recovery, retry, job state, monitoring을 직접 관리해야 한다.

문제의 요구사항이 serverless solution이라면 EC2를 도입할 이유가 없다. S3 자체의 대규모 객체 관리 기능을 사용하는 편이 자연스럽다.

8. AWS Batch와 S3 Batch Operations는 다르다

서비스목적이번 문제와의 관계
AWS Batch일반적인 batch computing workload 실행범용 compute라 요구사항보다 무거울 수 있음
S3 Batch OperationsS3 객체 집합에 대규모 작업 수행수백만 개 객체 관리 작업에 직접 적합

문제의 중심이 수백만 개 S3 객체에 같은 관리 작업을 수행하는 것이라면 S3 Batch Operations를 먼저 생각하는 것이 좋다.

9. Glacier Deep Archive인데 객체를 복원해야 할까?

객체가 Glacier Deep Archive에 있다고 해서 삭제하기 위해 객체 내용을 먼저 restore할 필요는 없다. Restore가 필요한 것은 일반적으로 archived object의 내용을 다시 읽어야 할 때다.

Read Object Content -> restore 필요할 수 있음
Delete Object       -> restore 없이 metadata 기반 처리 가능

10. Lifecycle Rule과는 무엇이 다른가?

모든 객체를 생성 후 3년 뒤 삭제한다면 S3 Lifecycle Rule이 훨씬 단순하다. 하지만 이번 요구사항에는 일부 객체는 계속 보존한다는 예외가 있다.

flowchart TB simple[정형화된 지속적 보존 정책] --> lifecycle[S3 Lifecycle] complex[특정 객체 집합에 대한 대규모 일회성 작업] --> inventoryBatch[S3 Inventory + Batch Operations]

복잡한 대상 선정이나 일회성 대규모 정리 작업이라면 Inventory, manifest/filtering, Batch Operations 방식이 더 적합할 수 있다.

11. 왜 Glue Crawler가 필요하지 않을까?

Glue Crawler는 S3 데이터를 스캔해 schema를 파악하고 Glue Data Catalog에 등록하는 데 사용된다. 하지만 이번 문제에서 필요한 것은 schema가 아니라 object key, last modified, 보존 여부를 이용한 객체 관리다.

따라서 Glue Crawler를 끌어들이는 것은 문제에 비해 지나치게 복잡하다.

12. SAA에서 선택지를 제거하는 방법

flowchart TB ec2[EC2 Script] --> ec2No[Serverless 요구와 충돌] awsBatch[AWS Batch] --> batchNo[S3 객체 관리 전용 기능보다 무거움] crawler[Glue Crawler] --> crawlerNo[Schema discovery 중심] s3ops[S3 Inventory + Batch Operations] --> yes[Millions of S3 Objects + Bulk Operation에 적합]

13. 마무리

S3 객체가 몇 개 없을 때는 단순한 script로도 충분하다. 하지만 규모가 수백만 개가 되면 직접 반복문을 작성하는 것보다 대상을 정의하고 관리형 서비스에 실행을 맡기는 구조가 더 중요해진다.

Inventory는 대상을 찾고, Batch Operations는 대상에 작업한다.

수백만 개의 S3 객체를 직접 순회하는 애플리케이션을 만들기 전에 S3가 제공하는 대규모 관리 기능을 먼저 확인해야 한다.
