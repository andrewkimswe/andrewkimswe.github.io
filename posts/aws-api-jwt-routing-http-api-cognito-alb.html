AWS · API · Security

[AWS/API] JWT 인증과 경로 기반 라우팅을 함께 구현하려면? - API Gateway HTTP API, Cognito, ALB

JWT 인증과 URL path 기반 backend routing은 같은 문제가 아니다. Cognito, API Gateway HTTP API, ALB의 책임을 나누면 인증 계층과 application routing 계층을 깔끔하게 분리할 수 있다.

2026.08.25AWSAPI GatewayCognito

하나의 API가 여러 백엔드 서비스를 호출하는 구조를 생각해보자.

/api/users
/api/orders
/api/payments

각 요청은 JWT를 이용해 인증된 사용자만 호출할 수 있어야 하고, URL path에 따라 서로 다른 backend service로 전달되어야 한다.

flowchart LR auth[Authentication / Authorization
JWT] --> api[API Layer] routing[Routing
Layer 7 Path-based Routing] --> api

AWS에서는 이를 API Gateway HTTP API, Amazon Cognito, Application Load Balancer 조합으로 구성할 수 있다.

1. 전체 구조

flowchart TB client[Client] -->|JWT| httpApi[API Gateway
HTTP API] cognito[Cognito User Pool] -->|Issuer / JWKs| httpApi httpApi -->|JWT Authorization| alb[Application Load Balancer] alb -->|/users/*| user[User Service] alb -->|/orders/*| order[Order Service] alb -->|/payments/*| payment[Payment Service]

Cognito는 사용자 인증과 token 발급, HTTP API는 API 진입점과 JWT 검증, ALB는 L7 path-based routing, backend는 실제 business logic을 담당한다.

2. JWT는 무엇인가?

JWT는 인증 및 권한 정보를 전달할 때 널리 사용되는 token 형식이다. 구조는 Header, Payload, Signature로 이루어진다.

{
  "sub": "user-123",
  "scope": "orders.read",
  "exp": 1790000000
}

API는 JWT를 검증해 누가 요청했는지, token이 유효한지, 만료되지 않았는지, 필요한 scope를 가지고 있는지를 판단한다.

3. Cognito와 HTTP API의 역할

Amazon Cognito User Pool을 사용하면 사용자 인증과 token 발급을 관리할 수 있다. 클라이언트는 이후 API 요청에 JWT를 포함한다.

Authorization: Bearer <JWT>

API Gateway HTTP API는 JWT Authorizer를 기본적으로 지원한다. JWT 검증을 애플리케이션마다 직접 구현하지 않아도 API 진입 계층에서 인증을 처리할 수 있다.

flowchart TB user[User] --> login[Cognito Login] login --> jwt[JWT] jwt --> http[HTTP API JWT Authorizer] http --> backend[Backend]

4. 왜 NLB가 아니라 ALB인가?

두 번째 요구사항은 path-based routing이다. /users/*, /orders/*, /payments/* 같은 HTTP path를 기준으로 backend를 선택하려면 Layer 7 기능이 필요하다.

flowchart TB alb[ALB] -->|/users/*| users[User Service] alb -->|/orders/*| orders[Order Service] alb -->|/payments/*| payments[Payment Service]

Network Load Balancer는 L4 중심의 load balancer라 TCP, TLS, UDP 레벨 연결 처리에 강하다. HTTP path를 기준으로 backend를 선택해야 한다면 ALB가 자연스러운 선택이다.

L7 HTTP Routing -> ALB
L4 TCP/UDP      -> NLB

5. API Gateway와 ALB를 둘 다 사용하는 이유

ALB도 HTTP를 처리하지만 API Gateway와 역할이 다르다. API Gateway는 API front door로 authentication, authorization, throttling, API management에 강하다.

ALB는 VPC 안의 여러 application backend에 대한 Layer 7 traffic distribution, path routing, host routing, target group 분리에 강하다.

flowchart TB internet[Internet] --> gateway[API Gateway
API/Auth Layer] gateway --> integration[Private Integration] integration --> alb2[ALB
Application Routing Layer] alb2 --> services[Services]

6. Private Integration

API Gateway HTTP API는 VPC Link를 사용해 VPC 내부 리소스와 private integration을 구성할 수 있다.

flowchart TB client2[Client] --> publicApi[Public API Gateway] publicApi --> vpclink[VPC Link] vpclink --> internalAlb[Internal ALB] internalAlb --> privateServices[Private Services]

이렇게 하면 backend service를 직접 인터넷에 노출하지 않고 API Gateway를 public entry point로 사용할 수 있다.

7. 요청 하나가 처리되는 과정

사용자가 GET /orders/123을 호출한다고 하자.

flowchart TB user2[User] --> cognito2[Cognito] cognito2 -->|JWT 발급| call[GET /orders/123
Authorization: Bearer JWT] call --> api2[HTTP API
JWT validation] api2 --> link2[VPC Link] link2 --> alb3[ALB] alb3 -->|/orders/*| order2[Order Service]

유효하지 않은 token이면 API Gateway에서 요청을 거부하고, 유효한 요청만 ALB를 통해 backend로 전달한다.

8. REST API는 언제 생각할까?

REST API가 잘못된 서비스라는 의미는 아니다. API Gateway의 더 많은 전통적 기능이나 특정 고급 기능이 필요한 환경에서는 여전히 사용할 수 있다.

하지만 요구사항이 HTTP API, JWT Authorization, Private Backend라면 HTTP API가 더 간단하고 비용 효율적인 선택이 될 수 있다.

9. SAA에서 빠르게 푸는 방법

flowchart TB jwtReq[JWT 인증] --> httpApi2[API Gateway HTTP API + Cognito] pathReq[Path-based Routing] --> alb4[Layer 7 ALB] nlb[NLB] --> reject[Path routing에는 부적합]

복합적인 AWS 아키텍처 문제일수록 서비스를 통째로 외우기보다 인증, 네트워크, 라우팅, 컴퓨팅처럼 요구사항을 계층별로 분리하는 것이 빠르다.

10. 마무리

이 아키텍처의 핵심은 AWS 서비스를 많이 사용하는 것이 아니라 각 계층의 책임을 분리하는 것이다.

Cognito    = Identity / Token
HTTP API   = API Entry / JWT Authorization
ALB        = L7 Application Routing
Backend    = Business Logic

시험에서는 두 문장만 기억해도 상당 부분 풀린다. JWT 기반 API 인증은 API Gateway HTTP API의 JWT authorization으로, HTTP path 기반 routing은 Layer 7 Application Load Balancer로 연결한다.
